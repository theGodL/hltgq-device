# mq 站点状态判断视频联调

日期：2026-10-20
参与方：hltgq-mq（采集入库/站点状态）、hltgq-device（视频设备状态）
目标：站点状态（`zebpsu`）判断纳入视频设备，解决"纯视频站点视频在线却显示离线"的问题

## 一、背景

站点-设备架构改造后，视频设备统一落在设备表 `t_auto_hltgq_water_device`（type 含 `#5#`），
在线状态由 hltgq-device 每小时按 ICC 设备树同步到 `status`（`#1#` 在线 / `#2#` 离线）。

站点表 `t_auto_hltgq_5nw74_vnqqef` 的状态列 `zebpsu` 目前由采集链路定时刷新。
纯视频站点没有采集设备，采集侧无数据可判，导致视频在线时站点仍被刷成离线。

## 二、数据库现状（2026-10-20 22:00 实测）

站点按设备构成分三类（严格口径：纯视频站 = 站点下不存在任何非视频设备，空类型也算非视频）：

| 类型 | 站点数 | 现状 |
|---|---|---|
| 只有视频设备（严格口径） | 28 | 16 个视频在线但 `zebpsu=#2#`（待改 `#1#`）；11 个视频全离线且 `zebpsu=#2#`；1 个（麻塘湖灌区）已是 `#1#` |
| 视频 + 其他设备（含空类型） | 122 | 汪元节制闸为 3 台视频 + 3 台空类型闸门设备，归此类 |
| 无视频设备 | 22 | 不涉及 |

视频设备：220 台，158 在线 / 62 离线。

更新痕迹：`2026-10-20 20:05:00` 有一批站点被刷新（同一时刻闸门设备 `#3#` 状态也在更新），
22 个纯视频站点最近 24 小时被 SYSTEM 更新过，判断为采集侧定时任务写入。

| Q2 | 刷新范围是全量站点还是仅有采集设备的站点 | 纯视频站点也被刷成 `#2#`，看行为是全量 |

## 四、最终判定规则（device 写纯视频站，mq 写其余）

按站点聚合设备：

- `video_cnt`：该站点 `type LIKE '%#5#%'` 的设备数
- `video_online`：其中 `status='#1#'` 的数量
- `other_cnt`：该站点非视频设备数（`type` 不含 `#5#`，空类型也算非视频）

判定与写入方：

1. `video_cnt > 0 AND other_cnt = 0`（纯视频站点）：由 **hltgq-device** 写——`video_online > 0` → `#1#`，否则 `#2#`
2. `other_cnt > 0`（混合站点）：**mq** 维持遥测口径，device 不写
3. `video_cnt = 0`（无视频设备）：**mq** 维持现有逻辑

不新增接口。纯视频站没有遥测，device 本地视频状态即可判定；混合站/无视频站依赖遥测，仍归 mq。
两边按站点类型分工，写入范围互斥，不会互相覆盖。

## 五、参考 SQL（金仓）

device 侧 `StationStatusSyncService.syncVideoOnlyStationStatus()` 按此口径查询纯视频站：

```sql
WITH v AS (
  SELECT site,
         count(*) AS video_cnt,
         count(*) FILTER (WHERE status = '#1#') AS video_online
  FROM "qixiao-apaas".t_auto_hltgq_water_device
  WHERE "type" LIKE '%#5#%'
  GROUP BY site
), n AS (
  SELECT site, count(*) AS other_cnt
  FROM "qixiao-apaas".t_auto_hltgq_water_device
  WHERE "type" IS NULL OR "type" NOT LIKE '%#5#%'
  GROUP BY site
)
SELECT s.id, s.zzkaec, s.zebpsu,
       COALESCE(v.video_cnt, 0) AS video_cnt,
       COALESCE(v.video_online, 0) AS video_online,
       COALESCE(n.other_cnt, 0) AS other_cnt
FROM "qixiao-apaas".t_auto_hltgq_5nw74_vnqqef s
LEFT JOIN v ON v.site = s.id
LEFT JOIN n ON n.site = s.id
WHERE COALESCE(v.video_cnt, 0) > 0
ORDER BY s.zzkaec;
```

只写状态变化的行（幂等，防无谓更新）：

```sql
UPDATE "qixiao-apaas".t_auto_hltgq_5nw74_vnqqef s
SET zebpsu = ?,
    updated_at = LOCALTIMESTAMP,
    updated_by = 'SYSTEM'
WHERE s.id = ?
  AND s.zebpsu IS DISTINCT FROM ?;
```

## 七、验收方法

1. 下一个整点同步后，device 日志出现 `[站点同步] 纯视频站点状态刷新: 纯视频站28个（在线17，离线11），更新16行`
2. 按第五节 SQL 核对：28 个纯视频站中 `video_online > 0` 的 17 个全部为 `#1#`；全离线的 11 个保持 `#2#`
3. 混合站点、无视频站点的状态与改动前逐行一致
4. mq 侧不再写纯视频站的 `zebpsu`（日志/行为均跳过）
5. site 页面站点状态与 `zebpsu` 一致
6. 观察一个完整小时周期（device 整点、mq :05），确认无状态振荡；人工/三方修改会被下个周期覆盖，属预期

## 八、已评估未采用的方案

- **mq 直读设备表判纯视频站**（mq 已实现的版本）：可行，但纯视频站归 device 判定更直接，最终改为 device 写、mq 排除。
- **mq 提供遥测接口、device 全量判站点**：需要接口、鉴权、超时降级，且 device 反向依赖 mq 的遥测数据；混合站仍以遥测为主，收益不大，不采用。
- **device 提供视频状态接口、mq 综合判定**：同库环境下接口只是把一次 SQL 换成一次 HTTP，多一层故障点，不采用。

mq 跳过条件（与 device 查询逐字一致）：

```sql
-- 满足以下条件的站点归 device，mq 不写 zebpsu
EXISTS (
  SELECT 1 FROM "qixiao-apaas".t_auto_hltgq_water_device v
  WHERE v.site = s.id AND v."type" LIKE '%#5#%'
)
AND NOT EXISTS (
  SELECT 1 FROM "qixiao-apaas".t_auto_hltgq_water_device d
  WHERE d.site = s.id
    AND (d."type" IS NULL OR d."type" NOT LIKE '%#5#%')
)
```

说明：当前设备 `type` 均为单值（`#5#` 220 台，无多类型视频设备），上述条件成立；
