# 大华视频对接方案（hltgq-device）

> 面向新加入项目的开发人员：本文说明本项目与大华 ICC 平台对接了哪些接口、怎么调用、关键约定与踩坑点。
> 代码位置：`com.qgyun.hltgq.hltgqdevice`（service/config/controller 包）。

---

## 一、对接总览

### 1.1 网络拓扑

```
浏览器/前端
   │
   ▼  HTTP（APaaS 会话鉴权）
┌────────────────────────────────────────────┐
│  hltgq-device（本服务）  10.68.18.4:18686   │
│  ├─ DahuaController         REST 接口层      │
│  ├─ Dahua*Service           大华 SDK 调用层   │
│  ├─ DahuaStreamProxyController  HLS 反向代理  │
│  └─ DahuaEventCallbackController 事件回调入口 │
└──────┬──────────────────────▲──────────────┘
       │ OAuth2 HTTPS         │ 事件回调 POST（HTTP，无鉴权）
       ▼                      │
┌────────────────────────────────────────────┐
│  大华 ICC 平台        60.175.44.252:9443    │
│  ├─ /evo-apigw/...    业务 API 网关（HTTPS） │
│  └─ 事件订阅/推送服务（IVSS 智能分析）        │
└──────┬─────────────────────────────────────┘
       │ 实时流/回放流（HLS，HTTP，仅内网）
       ▼
┌────────────────────────────────────────────┐
│  NVR 媒体服务器       192.168.14.20:7086    │
└────────────────────────────────────────────┘
```

要点：
- **业务 API**（设备树/流地址/录像/云台/事件订阅）走 ICC 公网网关 `60.175.44.252:9443`（HTTPS + OAuth2）；
- **媒体流**（实时预览/录像回放的 m3u8 与 TS 分片）走 NVR 内网 `192.168.14.20:7086`（HTTP + `?token=` 鉴权），**7086 端口仅内网可达，用公网 IP 会连接超时**；
- 本服务部署在政务云（10.68.18.4），与 ICC 内网同网段互通；ICC 平台向本服务推送事件（`ICC → 本服务` 方向）也必须可达。

### 1.2 依赖与调用方式

- SDK：`com.dahuatech.icc:java-sdk-oauth / java-sdk-common / java-sdk-core`，版本见 pom.xml（`icc.sdk.version`，当前 1.0.13.12）；
- 所有网关 API 统一走 `com.dahuatech.icc.oauth.utils.HttpUtils`：

```java
GeneralResponse gr = HttpUtils.executeJson(
        "/evo-apigw/...",              // 接口路径
        body,                          // 请求体 Map（自动 JSON 序列化）
        null,                          // 额外 header（通常 null）
        Method.POST,                   // 请求方法
        authService.getOauthConfig(),  // OAuth 配置（SDK 自动附加鉴权头）
        GeneralResponse.class
);
// gr.getResult() 可能是 String 或对象；String 时需再 JSON.parseObject
```

## 二、鉴权认证（OAuth2 password 模式）

### 2.1 配置项（application.properties → DahuaConfig）

| 配置 | 说明 |
|---|---|
| `icc.sdk.host` | 平台地址 `IP:端口`，如 `60.175.44.252:9443` |
| `icc.sdk.enable.https` | 是否 HTTPS（true） |
| `icc.sdk.grantType` | `password`（固定） |
| `icc.sdk.clientId` / `icc.sdk.clientSecret` | 凭据 ID / 凭据密钥（平台颁发） |
| `icc.sdk.username` / `icc.sdk.password` | 平台登录用户名 / 密码 |
| `icc.sdk.connection-timeout` / `read-timeout` | 连接/读超时（毫秒） |

### 2.2 代码约定

- `DahuaAuthService.init()`（@PostConstruct）构建 `OauthConfigUserPwdInfo`：
  - **host 只传 IP（不含端口）**，端口通过构造参数单独传——传 `IP:端口` 会导致 SDK 拼接出错；
  - 同时启动 `icc-token-preWarm` 后台线程预热 token（避免首次操作多花 1~2s 鉴权时间）；
- 获取 token：`HttpUtils.getToken(oauthConfig).getAccess_token()`，**SDK 内部自动管理 token 有效期与保活**，业务代码无需缓存/续期；
- 注意区分两种鉴权：
  - 网关 API（`/evo-apigw/...`）：SDK 自动附加 OAuth 鉴权头；
  - NVR 媒体流（7086 端口）：**URL 参数 `?token=` + 请求头 `X-Subject-Token`**（浏览器不能直连，由 hls-proxy 代理附加）。

## 三、设备树（组织/设备/通道）

### 3.1 接口

```
POST /evo-apigw/evo-brm/1.0.0/tree
```

请求体（懒加载，按父节点查直接子节点）：

```json
{
  "type": "001;;1",
  "id": "001",
  "checkStat": 1
}
```

- `id`：父节点 ID；空或 `"001"` 查根；
- 成功：`code="0"`，节点数组在 **`data.value`**（`data` 是 `{"value":[...]}` 结构，不是直接数组）。

响应节点字段（`DahuaDeviceService.DeviceTreeNode`）：

| 字段 | 含义 |
|---|---|
| `id` | 节点 ID（作为下次递归的 parentId） |
| `name` | 节点名称 |
| `pId` | 父节点 ID |
| `nodeType` | `org` 组织 / `dev` 设备 / `ch` 通道 |
| `isParent` | 是否有子节点（true 才递归，**id 为空时不要递归**，防误查根 001） |
| `isOnline` | 在线状态：**0=离线，1=在线** |
| `checkStat` | 状态检测使能标志（请求参数回显，**不是在线状态**） |
| `deviceCode` | 设备编码 |
| `cameraType` | 1=枪机(固定) 2=球机(PTZ) 3=半球 4=云台 |

### 3.2 项目用法

- 前端：`GET /api/dahua/device-tree?orgId=`（懒加载）；
- 站点同步（StationStatusSyncService）：每小时整点递归遍历整树，通道（`nodeType=ch`）的 **devicecode 取 `id` 字段**（如 `1000231$1$0$10`），兜底取 `deviceCode`；
- 轮巡检测（VideoAlertScheduler）：复用 `collectVideoChannels()` 遍历。

### 3.3 踩坑

- **在线判定只认 `isOnline`**：实测离线设备的 `checkStat` 也是 1，用 `checkStat==1 || isOnline==1` 会把全部设备误判在线；
- **API 失败与"无子节点"要区分**：两者都返回空列表。站点同步遍历中任何子树查询失败（网络抖动）都视为"遍历不完整"，此时**禁止**把缺失通道标离线（会误伤整个子树），只能下轮重试；
- 递归深度要设上限（防环），超限同样视为遍历不完整。

## 四、实时视频流（预览）

### 4.1 获取流地址

```
POST /evo-apigw/admin/API/video/stream/realtime
```

请求体：

```json
{
  "data": {
    "channelId": "1000231$1$0$10",
    "streamType": "1",
    "type": "hls"
  }
}
```

- `streamType`：`1` 主码流 / `2` 子码流；
- `type`：`hls` / `flv` / `rtmp`；
- 成功：`code="1000"`，流地址在 `data.url`。

响应示例（`data.url`）：

```
http://192.168.14.20:7086/live/cameraid/1000231%241%240%2410/substream/1.m3u8?token=xxx
```

### 4.2 降级与地址修正（DahuaVideoService 链路）

API 失败时按官方 demo 拼接 HLS 地址兜底：

```
http://{hls-host}:{hls-port}/live/cameraid/{deviceCode}%24{channelSeq}/substream/{streamType}.m3u8?token={token}
```

拿到原始地址后做两步修正：
1. **内网 IP 修正**（`ensureInternalHlsHost`）：目标端口为 7086 且 host 是公网 IP → 强制替换为 `icc.sdk.hls-host`（192.168.14.20），协议切 HTTP；
2. **包装代理地址**（`buildProxyUrl`）：返回 `/api/dahua/hls-proxy?url={URL编码后的地址}`——浏览器不带 token，必须走后端代理。

### 4.3 HLS 反向代理（DahuaStreamProxyController）

```
GET /api/dahua/hls-proxy?url={编码后的流地址}          （m3u8 与旧格式）
GET /api/dahua/hls-proxy/1_seg_0.ts?url={编码后的地址}  （TS 分片，文件名供 hls.js 识别类型）
```

代理职责：
1. 解码 `url` 后把 `$` 替换回 `%24`（**NVR 要求路径中 `$` 必须编码为 `%24`**，否则返回错误内容）；
2. 附加鉴权：`?token=` 参数 + `X-Subject-Token` 头；
3. 转发到 NVR，透传响应；
4. **m3u8 改写**：把清单中的 TS 分片地址全部改写为经过本代理的 URL（`/api/dahua/hls-proxy/{ts文件名}.ts?url=...`），保证每个分片都带鉴权；
5. **HEVC(H.265) 转码**：TS 分片扫描 PAT→PMT，`streamType==0x24` 判为 HEVC，调 ffmpeg 转 H.264（hls.js 原生不支持 HEVC-in-TS）；转码时按分片序号设置 **PTS 偏移 = seq × 2s**（每片独立 ffmpeg 进程，不设偏移会导致 PTS 不连续 → `bufferStalledError`）；
6. HEVC 判定结果按流路径缓存（`hevcStreamCache`），避免每个分片重复扫描 188 字节包。

### 4.4 智能码流探测（DahuaVideoService.getSmartHlsUrl）

播放前一次性探测，避免代理层中途切换 m3u8 导致 PTS 不连续：

1. 拉子码流 m3u8 → 拉首条 TS → 扫 PMT 判编码；
2. 子码流 H.264 → 直出子码流（带宽低、无需转码）；
3. 子码流 HEVC → 探测主码流：主码流 H.264 → 出主码流；主码流也 HEVC/不可用 → 出子码流（代理层转码）；
4. 结果按 channelId 缓存（`main`/`sub`）；主码流缓存失效时自动降级重探测；
5. 探测单次 HTTP 连接 3s、读 5s；M3U8 拉取失败（404/超时）返回"流不可用"，**不要把不可用误判为 H.264 直出**（会把无效 URL 返回前端触发 `manifestLoadError`）。

### 4.5 检测专用（视频告警轮巡）

- `resolveInspectionStreamUrl(channelId)`：取子码流原始地址（含 token），供 ffmpeg 抽帧直连，不写码流策略缓存、不影响播放链路；
- `isStreamAvailable(rawUrl)`：探测流是否可取（设备在线但取不到流 → "取流异常"故障候选）。

## 五、历史录像（回放）

### 5.1 月录像状态（前端月历标记）

```
POST /evo-apigw/admin/API/SS/Record/GetChannelMonthRecordStatus
```

请求体：`channelId`、`recordSource`（1=全部 2=设备 3=中心）、`month`（yyyyMM，如 202609）。
返回按天是否有录像的 0/1 序列（逗号分隔，`1`=当日有录像）。

### 5.2 录像信息查询（按文件分段）

```
POST /evo-apigw/admin/API/SS/Record/QueryRecords
```

请求体：`channelId`、`recordSource`、`startTime`/`endTime`（**单位：秒**）、`streamType`（0=所有 1=主 2=辅）、`recordType`（0=全部）。

返回录像段列表（`RecordSegment`），每段为一段录像文件。

> **回放不能跨录像文件**：前端必须先调 `/record/query` 拿到分段，再在单个段的时间范围内申请回放流。

### 5.3 录像回放流

```
POST /evo-apigw/admin/API/video/stream/record    （type=hls，ICC V5.0.12+）
```

请求体：`channelId`、`streamType`、`recordType`（1=普通 2=报警，与查询到的段类型一致）、`beginTime`/`endTime`（单位秒）、`recordSource`（2=设备 3=中心）。

回放流与实时流同为 7086 端口，拿到原始地址后走同一套处理：token 拼接 → 内网 IP 修正 → 包装为 `/api/dahua/hls-proxy?url=...`。

### 5.4 本项目对外接口

| 接口 | 说明 |
|---|---|
| `GET /api/dahua/record/month-status?channelId=&month=&recordSource=` | 月历录像标记 |
| `GET /api/dahua/record/query?channelId=&startTime=&endTime=` | 录像段列表（秒级时间戳） |
| `GET /api/dahua/record/stream?channelId=&beginTime=&endTime=` | 回放代理地址（不跨文件） |

## 六、云台控制（PTZ）

> 权限：仅系统管理员（`@RequireAdmin` + hltgq_default_admin 角色判定）；前端控制面板显隐由 `GET /api/dahua/auth/current-user` 的 `isAdmin` 决定。
> 前端提交前已按 `cameraType=2`（球机）校验，后端只做通道格式校验。

### 6.1 方向控制

```
POST /evo-apigw/admin/API/DMS/Ptz/OperateDirect
```

```json
{
  "data": {
    "channelId": "1000230$1$0$0",
    "direct": "1",
    "stepX": "5",
    "stepY": "5",
    "command": "1",
    "extend": ""
  }
}
```

| 参数 | 说明 |
|---|---|
| `direct` | 方向码：1=上 2=下 3=左 4=右 5=左上 6=左下 7=右上 8=右下 |
| `stepX`/`stepY` | 速度 1~8 |
| `command` | **1=开启动作（START），0=停止动作（STOP）** |
| `extend` | 空字符串 |

关键规则（官方文档要求）：
- **STOP 必须与 START 的 stepX/stepY/direct 保持一致，否则设备无法停止**（本项目缓存每通道最后一次 START 的 step）；
- 指令异步下发到设备端，**START 与 STOP 之间需间隔一定时间保证顺序执行**——本项目用自适应延迟：距 START 完成不足 150ms 时补足差值，超过则零延迟直发；
- 历史教训：START/STOP 值写反（0/1 互换）、STOP 用 stepX=0 与 START 不匹配，都会导致设备不可控。

### 6.2 镜头控制（变焦/聚焦/光圈）

```
POST /evo-apigw/admin/API/DMS/Ptz/OperateCamera
```

```json
{
  "data": {
    "channelId": "1000230$1$0$0",
    "operateType": "1",
    "direct": "1",
    "step": "5",
    "command": "1",
    "extend": ""
  }
}
```

| 参数 | 说明 |
|---|---|
| `operateType` | 1=变倍(zoom) 2=聚焦(focus) 3=光圈(iris) |
| `direct` | 1=增加（放大/聚焦近/光圈大）2=减小（缩小/聚焦远/光圈小） |
| `command` | 1=START，0=STOP（STOP 参数与 START 一致，无历史 START 参数时跳过 API） |

### 6.3 通道 ID 归一化

前端可能传短格式（纯设备编码 `1000230`），ICC 要求完整格式 `deviceCode$channelType$streamType$channelSeq`：

- 已含 `$` → 原样使用；
- 短格式 → 补齐为 `{code}$1$0$0`（`$1`=视频通道，`$0`=码流，`$0`=首通道序号）；
- 校验：第一个 `$` 后的数字必须是 `1`（视频通道），否则疑似非视频通道，记告警日志。

### 6.4 本项目对外接口（异步受理，PtzCommandDispatcher 串行调度）

| 接口 | Body |
|---|---|
| `POST /api/dahua/ptz/direct` | `{"channelId","direction"(up/down/left/right/upleft/upright/downleft/downright),"speed"}` |
| `POST /api/dahua/ptz/stop` | `{"channelId","direction"(可选)}` |
| `POST /api/dahua/ptz/lens` | `{"channelId","action"(zoomIn/zoomOut/focusIn/focusOut/irisIn/irisOut/stop),"speed"}` |

## 七、IVSS 智能事件接入（智能分析）

### 7.1 事件订阅（本服务 → ICC）

```
POST /evo-apigw/evo-event/1.0.0/subscribe/mqinfo
```

订阅体（`DahuaEventSubscribeService.buildSubscribeBody`）：

```json
{
  "param": {
    "monitors": [
      {
        "monitor": "http://10.68.18.4:18686/api/dahua/event/receive",
        "monitorType": "url",
        "events": [
          {
            "category": "alarm",
            "eventType": 2,
            "subscribeAll": 1,
            "domainSubscribe": 2,
            "authorities": [ { "orgs": ["..."], "nodeCodes": [] } ]
          }
        ]
      }
    ],
    "subsystem": {
      "subsystemType": 0,
      "name": "10.68.18.4_18686",
      "magic": "10.68.18.4_18686"
    }
  }
}
```

字段说明：
- `monitor`：回调地址（ICC 服务器可 POST 到的本服务地址）；
- `magic`：订阅者标识 = 回调地址的 `IP_端口`（如 `10.68.18.4_18686`），`subsystem.name` 与 `magic` 同值；
- `eventType=2`：只要报警、不要事件（0=都要，1=只要事件）；
- `subscribeAll=1`：订阅全部报警类型（**alarmType 码值随现场平台动态生成，无静态码表**，处理侧按 `alarmTypeName` 透传生成告警内容）；
- `orgs`：订阅组织码（`icc.sdk.event.orgs`，逗号分隔）。**官方并集规则：orgs 与 nodeCodes 是并集（A||B），仅按 orgs 过滤时必须显式 `nodeCodes=[]`，否则 nodeCodes 缺省=订阅所有，orgs 过滤失效**。留空=订阅全部，由处理侧按 nodeCode 过滤；
- 成功判定：响应 `success=true`。

刷新策略（防订阅丢失）：
- 应用启动即异步订阅（不阻塞启动）；
- **每小时整点刷新一次**：接口幂等（同 name/magic 覆盖原订阅，不产生重复），即使已订阅成功也每次刷新——防 ICC 平台侧订阅丢失（平台重启/人工误删）后本侧不自知导致事件链路静默中断，整点刷新即自愈。

### 7.2 事件回调（ICC → 本服务）

```
POST /api/dahua/event/receive     （路径在 AuthInterceptor 固定白名单，无鉴权放行）
```

平台推送的通用事件格式（callback 即 subscribe 的 monitor 地址，`ContentType=application/json`）：

```json
{
  "category": "alarm",
  "method": "alarm.msg",
  "uuid": "平台事件唯一标识",
  "info": {
    "nodeCode": "1000231$1$0$10",
    "alarmTypeName": "区域入侵",
    "alarmType": 101,
    "alarmGrade": 2,
    "alarmStat": 1
  }
}
```

- 响应契约：**立即返回 `{"code":"0","message":"成功"}`** 即视为受理成功；业务处理在后台线程池（2 线程）异步执行，避免阻塞平台推送；
- `alarmStat` 语义：**1=报警产生，2=报警消失**；
- `alarmGrade`：1~4（映射告警级别 #1#~#4#，缺失默认 #2#）；
- 官方回调格式**没有 alarmTypeName 静态码表**（码值随现场平台动态生成）：事件名优先透传 `alarmTypeName`，缺失兜底 `alarmType` 码值（`智能事件{码值}`），两者皆无则丢弃。

处理链路（VideoEventService.handleEvent）：
1. 仅处理 `category=alarm && method=alarm.msg`，其余忽略；
2. `uuid` 内存幂等去重（1 小时窗口，防平台重推）；
3. `nodeCode` → 站点表匹配（`devicecode = ? AND epjutj LIKE '%#5#%'`，防同 devicecode 的闸门/水质站点误命中），未匹配=非视频子系统事件，丢弃；
4. 站点 → 视频设备（code 匹配，查不到自动兜底创建）；
5. `alarmStat=1` → 新增告警（content=`{站点}-视频智能事件 {事件名}！`，type=#3# 智能分析，工单 qjulvf=#pfqj# 安全隐患整改）；
6. `alarmStat=2` → 按 content 关闭告警并联动关闭工单（仅 #1# 待处理工单）。

### 7.3 事件分页查询（轮询兜底）

回调可能因网络抖动丢失，每轮视频轮巡（30 分钟节拍）结束后按时间窗补拉：

```
POST /evo-apigw/evo-event/1.2.0/alarm-record/page
```

```json
{
  "pageNum": 1,
  "pageSize": 500,
  "alarmStartDateString": "2026-09-07 10:05:00",
  "alarmEndDateString": "2026-09-07 10:35:00"
}
```

- 成功：`code="0"`，记录在 `data.pageData`；
- 时间格式 `yyyy-MM-dd HH:mm:ss`（系统默认时区）；
- 游标语义：拉取成功推进 `lastPullTime`，**失败游标不推进**（下轮重拉同窗口，重复由幂等兜底）；
- 查询记录无平台 uuid，构造 `poll_{alarmCode}_{alarmStat}` 与回调路径区分；跨路径重复由告警 content 三字段去重兜底；
- 单页 500 条截断（30 分钟窗口内事件量远小于此值）。

## 八、通道 ID 格式约定

ICC 通道 ID 标准格式：`deviceCode$channelType$streamType$channelSeq`

| 字段 | 说明 |
|---|---|
| deviceCode | 设备编码，如 `1000231` |
| channelType | 通道类型：`1`=视频通道 |
| channelSeq | 通道序号，如 `10` |

- 示例：`1000231$1$0$10`；
- 设备树中通道节点的 `id` 字段即完整格式 devicecode（站点同步用它做设备匹配键）；
- HLS 地址拼接时 `$` 需编码为 `%24`（NVR 要求）；
- PTZ 短格式归一化：`1000230` → `1000230$1$0$0`。

## 九、常见坑速查

| 坑 | 说明 |
|---|---|
| 7086 端口走公网 IP | NVR 媒体服务仅内网可达，公网 `60.175.44.252` 连 7086 会超时；必须用 `icc.sdk.hls-host`（192.168.14.20） |
| 成功码不统一 | `evo-brm`/`evo-event` 系列 `code="0"`；`evo-apigw/admin/` 系列 `code="1000"`；订阅接口看 `success=true` |
| checkStat ≠ 在线状态 | 离线设备 checkStat 也是 1；在线判定只认 `isOnline` |
| PTZ START/STOP 参数 | STOP 与 START 的 step/direct 必须一致；间隔 ≥150ms；command 1=START 0=STOP |
| orgs/nodeCodes 并集 | 仅按 orgs 订阅时必须显式 `nodeCodes=[]`，否则退化为订阅所有 |
| 回放跨文件 | beginTime/endTime 不能跨录像文件，必须先 QueryRecords 拿分段 |
| URL 中 `$` 编码 | NVR 路径要求 `$` 为 `%24`，代理层解码后必须替换回去 |
| HEVC 转码 PTS | 每 TS 分片独立 ffmpeg 进程，PTS 偏移=分片序号×2s，否则 hls.js 报 bufferStalledError |
| 事件回调契约 | 受理即返回 code=0；业务异步处理；uuid 幂等 + content 三字段去重双保险 |
