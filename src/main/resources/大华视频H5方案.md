## 一、总体结论（先看这个）

1. **后端几乎零改动**：三页所需数据全部由现有 `DahuaController` 接口提供（设备树/流/云台/录像/权限），H5 只是新增 3 个静态 HTML 页面；
2. **权限控制天然一致**：`AuthInterceptor` 拦截**所有**请求（页面 + API），H5 页面与 PC 页面走同一条鉴权链路，不需要为 H5 单独写权限代码；
3. **与原型的两处差异需拍板**：回放页（原型按 mp4 文件列表设计，实际 ICC 按时间段录像段）与 AI 检测状态栏（对应 IVSS 智能事件，需新增一个轻量查询接口）。

## 二、权限控制对照（PC 与 H5 一致矩阵）

### 2.1 现有 PC 端权限机制（H5 直接继承）

| 机制 | 实现 | 对 H5 是否生效 |
|---|---|---|
| 登录校验 | `AuthInterceptor.preHandle` 拦截所有请求；无会话时：页面导航（Accept 含 text/html）302 跳平台登录页；AJAX 返回 401 JSON（含 `redirectUrl`）。**按来源区分登录页**：PC 页面/接口 → `http://220.179.1.110:8081/login/user/login`；H5（`/mobile/` 路径或 Referer 含 `/mobile/`）→ `http://220.179.1.110:8081/hlt/#/login/user/login` | ✅ 自动生效（H5 页面和 fetch 请求都是普通 HTTP 请求） |
| 会话凭证 | 三种来源任意其一：Header `X-Session-Id` / `Authorization` / Cookie `sessionId`（形如 `dev_hltgq_session:xxx`）；HGETALL 平台 Redis 会话 Hash 存在即登录 | ✅ H5 与平台同域时 Cookie 自动携带（PC monitor.html 即此模式）；跨域时 JS 手工读 Cookie 加 `X-Session-Id` 头 |
| 云台管理员权限 | `POST /api/dahua/ptz/*` 标注 `@RequireAdmin`，非系统管理员（超管或 hltgq_default_admin 角色）返回 403 | ✅ 后端强制，H5 无法绕过 |
| 云台面板显隐 | `GET /api/dahua/auth/current-user` 返回 `{userId, isAdmin}`，前端按 isAdmin 控制云台面板 | ✅ H5 复用同一接口 |
| 敏感接口降级保护 | 会话服务（Redis）不可用 → 503，**不降级放行** | ✅ 自动生效 |
| 白名单 | 仅 `/error` 与 `/api/dahua/event/`（ICC 事件回调）；H5 页面**不在**白名单 | ✅ H5 页面必须登录才能访问 |

### 2.2 H5 各页面权限矩阵

| 页面/功能 | 权限要求 | 前端处理 |
|---|---|---|
| 视频监视（列表页） | 已登录 | 未登录 → 302 跳平台登录页（拦截器处理，页面无需代码） |
| 实时监控（播放） | 已登录 | fetch 401 → `location.href = resp.redirectUrl` |
| 回放列表 / 回放播放 | 已登录 | 同上 |
| 云台控制盘 | **系统管理员** | 进入详情页调 `/auth/current-user`：`isAdmin=false` → 云台盘置灰 + 提示「仅系统管理员可操作」；`isAdmin=true` → 显示。操作接口被后端二次校验（403 兜底提示） |
| 权限服务异常 | — | 403 → toast「无操作权限，仅系统管理员可操作」；503 → toast「权限服务不可用，请稍后重试」 |

### 2.3 入口方式

- 平台（hltgq-site）H5 菜单链接 → `http://220.179.1.110:8081/hltgq-device/mobile/monitor.html`（nginx 统一前缀入口，推荐）；
- 内网直连 → `http://10.68.18.4:18686/mobile/monitor.html`（无前缀，同样可用）；
- 两种入口前端自动适配（见第十章），无需为入口写死前缀；
- 会话复用平台登录态（同域 Cookie）；若 H5 部署在非同域环境，页面 JS 从 Cookie 读 `sessionId` 并给所有 fetch 加 `X-Session-Id` 头（PC 端已有此兼容逻辑，照抄）。

|---|---|---|
| 视频监视（列表） | `static/mobile/monitor.html` | 页面 1 |

## 四、接口复用清单（后端改动评估）

### 4.1 直接复用（零改动）

| 原型需求 | 现有接口 | 说明 |
|---|---|---|
| 列表页摄像头卡片 | `GET /api/dahua/device-tree?orgId=` | 递归/逐级拉取；通道节点即摄像头（`isOnline` 判在线，离线即原型"离线态"） |
| 统计标签行（在线/离线/告警数） | 同上 + 前端统计 | 在线/离线由 isOnline 统计；告警数见 4.2 |

| 实时播放 | `GET /api/dahua/stream-url?channelId=&protocol=hls` → `/api/dahua/hls-proxy?url=` | 与 PC 同一链路（含内网修正/HEVC 转码），hls.js 播放 |
| 云台方向/停止 | `POST /api/dahua/ptz/direct`、`POST /api/dahua/ptz/stop` | 接口复用零改动（后端 @RequireAdmin + 串行调度）；防失控机制见 5.2 |
| 镜头控制 | `POST /api/dahua/ptz/lens` | 原型控制盘仅方向键 + 停止，一期可不做镜头按钮（接口预留） |
| 回放列表数据 | `GET /api/dahua/record/query?channelId=&startTime=&endTime=` | 见 4.3 差异说明 |
| 回放播放 | `GET /api/dahua/record/stream?channelId=&beginTime=&endTime=` | 复用 hls-proxy 播放 |
| 云台面板权限 | `GET /api/dahua/auth/current-user` | 前端显隐控制 |

### 4.2 已落地（方案 A）：`GET /api/dahua/alert/active`

原型列表页统计行有「🔴 告警 N」，详情页有「AI 检测状态栏」。方案 A 已实施，后端新增 `AlertQueryService` + 接口（仅登录，无管理员限制）：

- 不带 channelId → 汇总：`{total: 告警总数, byChannel: {通道devicecode: 未关闭告警数}}`（告警表 JOIN 设备表按通道分组，status IS DISTINCT FROM #4#）；
- 带 channelId → 该通道未关闭告警列表（content/time/type/level/status，按时间倒序，type=#3# 即 IVSS 智能事件）；
- 测试：AlertQueryServiceTest 3 用例（按通道聚合/单通道查询/空结果）。

### 4.3 与原型的差异点（需拍板）

**回放页数据口径**：原型设计为「mp4 文件列表（文件名/大小/时长）」，但 ICC 平台不提供 mp4 文件列表，只有**时间段录像段**（`record/query` 按秒级时间区间分段，PC 端 playback.html 同为该口径）。建议 H5 按段展示：

- 卡片文件名行 → 时间段（如 `8月31日 14:30 ~ 14:35`），与 PC 回放口径一致；
- 时长 = 段结束-开始；「大小」ICC 不提供，去掉；
- 播放按钮 → 先取段内时间范围再调 `record/stream`（回放不能跨段，接口注释已声明）。

若必须贴近原型 mp4 形态，只能在平台侧做下载/转封装，成本高，不推荐。

## 五、各页面实施要点

### 5.1 视频监视（monitor.html）

- 复用 PC 设备树接口：首屏拉根节点（orgId 空默认 001）→ 逐级懒加载或一次性递归拉平（151 通道量小，建议递归拉平后本地渲染，搜索即本地过滤）；
- 卡片三态：`isOnline=1` 在线（绿点/「在线」Tag）、`isOnline=0` 离线（灰点/「离线」Tag，可附最后断开时间——暂无该数据源，一期显示「离线」即可）、有未关闭告警 → 告警态（红点/告警 Tag，数据源见 4.2）；
- 卡片左图：原型为摄像头占位图标；一期用静态占位图（真实缩略快照需拉流截帧，成本高，列评估项）；
- 统计行：`在线 N / 离线 M / 告警 K`（K 依赖 4.2 方案 A）；
- 点击卡片 → `live.html?channelId={devicecode}&name={名称}`（名称 URL 编码传递，供导航栏标题）。

### 5.2 实时监控（live.html）

- 播放：进入后调 `stream-url` → hls.js 加载 `/api/dahua/hls-proxy?url=`；`<video>` 加 `muted playsinline webkit-playsinline`（iOS 必须，否则强制全屏）；进入即静音自动播（移动端允许静音自动播放），被浏览器拦截时静默显示播放按钮，不显示技术性提示文案；
- 左上角叠加信息（水位/流量）：原型中的水位/流量为水利业务数据，不属于本服务数据源（对应站点可能无水位监测）。一期不显示或留白（PC 端 monitor.html 是否已有同款信息？若无则 H5 一致不显示）；
- 云台控制盘：
  - 交互：`touchstart`（或 pointerdown）→ `ptz/direct`（START）；`touchend/touchcancel` → `ptz/stop`（STOP）。必须处理 `touchend` 否则按钮松开不停止（设备持续转动）；
  - 防失控加固（已完成，H5 与 PC 行为一致）：按住方向键持续转动、松开立即停止；快速点一下、按住切后台/锁屏、关闭页面等场景均自动停止，不会出现「转不停」；
  - 权限：页面加载时调 `current-user`，`isAdmin=false` → 控制盘置灰不可点 + 角标提示；后端 403 兜底 toast；
- 右上「回放」按钮 → `playback.html?channelId=`；
- AI 检测状态栏：按 4.2 方案 A 查该通道未关闭智能告警（`type=#3#`）：有 → 红字「检测到：{事件名}」；无 → 绿字「当前画面未检测到异常」。

### 5.3 回放列表（playback.html）

- 数据：默认展示最近一天（或按原型加日期筛选，复用 `record/month-status` 月历标记能力可选做）；
- 卡片：时间段 + 日期；点击录像段 → 跳独立播放页 `playback-player.html`（参数 channelId/beginTime/endTime/recordType/recordSource，风格与列表页一致），支持播放/暂停与倍速 0.5x~2x；
- 刷新按钮：重新拉 `record/query`。

## 六、移动端适配要点（与 PC 的差异）

| 项 | 说明 |
|---|---|
| viewport | `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`，适配刘海/底部横条（safe-area-inset） |
| hls.js | 与 PC 一致用 1.5.17 CDN；移动端原生支持 HLS 的 iOS Safari 优先走原生（`Hls.isSupported()` 判定），Android Chrome 走 MSE |

| 401 处理 | fetch 统一封装：401 → `location.href = redirectUrl`；403/503 → toast（见 2.2） |

## 十、nginx 统一前缀适配（已落地）

### 10.1 背景

nginx 代理由「每个页面/接口一个 location」改为**统一前缀 location**（rewrite 掉前缀后转发 18686）：

```nginx
# ====== hltgq-device 视频监控服务（容器 10.68.18.4:18686）======
location /hltgq-device/ {
    rewrite ^/hltgq-device(.*)$ $1 break;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $http_connection;
    proxy_buffering off;                     # HLS 流禁用缓冲
    proxy_read_timeout 120s;                 # HEVC ffmpeg 转码慢链路需宽限
    proxy_pass http://10.68.18.4:18686;
}
```

新增页面/接口**无需再改 nginx**；后端感知不到 nginx 前缀（rewrite 后收到无前缀路径），适配全部在前端完成。

### 10.2 前端自动感知机制（6 个页面统一模式）

```js
// 经 /hltgq-device/ 代理访问时自动补前缀；直连部署自动不补，两种入口通用
const APP_BASE = location.pathname.indexOf('/hltgq-device/') === 0 ? '/hltgq-device' : '';
const API_BASE = APP_BASE + '/api/dahua';
function appUrl(path) { return APP_BASE + path; }   // 页面跳转补前缀
function proxyUrl(path) {                           // 后端返回的绝对代理地址补前缀
  if (!path) return path;
  if (path.indexOf('/api/') === 0) return APP_BASE + path;
  return path;
}
```

| 适配点 | 规则 |
|---|---|
| 接口请求 | 统一用 `API_BASE` 拼接（前缀自动带） |
| 页面跳转 | 绝对路径经 `appUrl()`（相对路径如 `'playback.html'` 天然兼容无需改） |
| 播放地址 | `playHls` 开头统一 `proxyUrl()`（后端返回 `/api/dahua/hls-proxy?...`） |
| 登录 302/401 redirectUrl | 平台登录页绝对 URL，不受前缀影响；PC 与 H5 分别跳 PC/H5 登录页（见 2.1，拦截器按 /mobile/ 路径或 Referer 判定） |

### 10.3 后端 1 处配套修改

`DahuaStreamProxyController.rewriteM3u8` 的 TS 分片地址由绝对 `/api/dahua/hls-proxy/{ts}?url=` 改为**相对** `hls-proxy/{ts}?url=`：

- 浏览器以 m3u8 响应 URL 为基准解析：带前缀时自动解析到 `/hltgq-device/api/dahua/hls-proxy/{ts}`，直连时解析到 `/api/dahua/hls-proxy/{ts}`，两种部署均命中控制器；
- 若保持绝对路径，前缀模式下分片请求会绕过 nginx location 直接 404，视频无法播放。

### 10.5 新增页面/接口规范（沿用即可，无需改 nginx）

1. 新页面顶部复制 10.2 的 5 行常量与函数；
2. 所有 fetch 用 `API_BASE` 拼接；所有页面跳转绝对路径经 `appUrl()`；后端返回的 `/api/...` 播放/资源地址经 `proxyUrl()`；

## 十一、平台 H5 项目集成指南（给前端）

### 11.1 集成结论（先看这个）

视频 H5 自成闭环：`视频监视 → 实时监控（含云台） → 回放列表 → 回放播放`，页面间跳转、返回、登录鉴权、云台权限全部在页面内部完成。

**平台 H5 前端只需要一个入口地址，零 API 对接、零额外配置：**

```
http://220.179.1.110:8081/hltgq-device/mobile/monitor.html
```

> 本文第一至十章为服务内部实现说明，平台前端接入无需阅读，看本章即可。

### 11.2 两种集成方式

| 方式 | 做法 | 说明 |
|---|---|---|
| A. 菜单/按钮整页跳转（推荐） | 菜单项或按钮直接 `location.href = 入口地址`（或 `<a>` 标签） | 零风险：登录 302、视频全屏、iOS 播放等行为全部正常；返回按钮由视频页自身 history 闭环 |
| B. iframe 嵌入 | 在平台页面内 `<iframe>` 加载入口地址 | 需注意 11.3 的 iframe 限制，适合「平台页面内嵌视频列表」的场景 |

### 11.3 iframe 嵌入注意事项（方式 B 必读）

1. **iOS 播放必须加 `allow` 属性**，否则 iframe 内视频无法自动播放/播放：

```html
<iframe src="http://220.179.1.110:8081/hltgq-device/mobile/monitor.html"
        style="width:100%;height:100%;border:0"
        allow="autoplay; fullscreen; encrypted-media; picture-in-picture">
</iframe>
```

2. **未登录时 302 会发生在 iframe 内部**（登录页被嵌在 iframe 里，体验不佳）。建议：
   - 平台 H5 保证用户已登录后再展示视频入口（正常流程用户必然已登录）；
   - 或平台 H5 菜单用方式 A（整页跳转），登录跳转在顶层窗口自然完成；
3. iframe 容器需给出明确高度（如 `height: 100%` 或固定 px），视频页为全屏自适应布局，无滚动条。

### 11.4 会话与权限（前端无需处理）

| 项 | 说明 |
|---|---|
| 登录会话 | 视频页与平台 H5 同域（`220.179.1.110:8081`），浏览器自动携带平台会话 Cookie，**登录一次平台后视频页免登录** |
| 未登录跳转 | 视频页后端自动 302 到 H5 登录页 `http://220.179.1.110:8081/hlt/#/login/user/login`（拦截器按 `/mobile/` 路径判定，见 2.1） |
| 云台权限 | 页面内自动判断（系统管理员才显示云台盘，非管理员置灰），无需前端传任何用户信息 |
| 接口调用 | **无**。视频页所有数据由后端接口提供，平台前端不需要也不应直接调 `/api/dahua/*` |
| 域名/端口变更 | 只需改入口地址的域名端口，页面内部全相对感知（nginx 前缀自动适配），无需改任何代码 |

### 11.5 页面闭环（集成后平台前端不参与）

```
monitor.html ──点击卡片──▶ live.html?channelId= ──回放按钮──▶ playback.html?channelId=
                                              │                       │
                                              │                   点击录像段
                                              │                       ▼
                                              └─────返回────── playback-player.html（倍速/暂停）
```

- 各页返回按钮：有历史则 `history.back()`，无历史则回 `monitor.html`，闭环不跳出；
- 平台 H5 若从 iframe 外部发消息控制（如强制刷新），视频页无自定义消息协议，非必要不做。
